# 漫画标签管理工具 · 需求分析与方案规划

> 版本 v0.1（需求确认稿） · 2026-08-30 · 状态：待确认

## 0. 一句话概述

做一个本机小工具：把「按单本分文件夹保存的漫画库」变成可视化管理界面——总览所有漫画、按 tag 筛选、给单本手动打 tag（输入或从现有选择）、随时增删改 tag。所有 tag 由用户手动输入并确认，不做任何自动识别。

## 1. 背景与问题

- 现状：漫画按单本分文件夹保存；文件夹名只能体现名字，承载不了剧情类型等 tag 信息。
- 痛点：漫画多了以后无法按类型筛选，找起来靠记忆；每本的 tag 信息无处安放。
- 目标：**不改变**现有文件夹组织方式，附加一层「tag 元数据」，提供总览 / 筛选 / 编辑能力。

## 2. 核心流程

角色：唯一本地用户。

主流程：

1. 打开工具 → 扫描总文件夹 → 总览所有漫画（卡片：封面缩略图 + 名称 + tag）。
2. 顶部 tag 栏点选 → 按类型筛选；点卡片 → 进入单本详情。
3. 详情页：查看该本全部 tag；新增（输入新 tag / 从现有选择）；删除；修改。
4. 新入库：把新漫画文件夹拷进总文件夹 → 工具识别为「未分类」→ 进入详情打 tag 保存。
5. （可选）全局标签管理：查看每种 tag 的漫画数，全局改名 / 合并 / 删除。

## 3. 功能需求

### 3.1 功能清单（必须有 / 应有 / 可以有）

**必须有（MVP）**

- F1 扫描总文件夹，识别每个子文件夹为一本漫画。
- F2 总览视图：卡片网格，显示名称 + tag（+ 封面若有）。
- F3 按 tag 筛选（单选即可，多选组合见 F12）。
- F4 单本详情：tag 列表、文件夹路径、「打开文件夹」按钮。
- F5 打 tag：输入新 tag（回车确认）或从现有 tag 下拉 / 点选。
- F6 编辑 tag：增加 / 删除 / 修改（改某本的一个 tag，或全局改名）。
- F7 未分类提醒：无 tag 的文件夹自动标记「未分类」，便于新入库后处理。
- F8 数据持久化：tag 数据保存为本地文件，重启不丢。

**应有（Should）**

- F9 封面显示：自动取文件夹内第一张图片（或 cover.jpg）作缩略图。
- F10 全局标签管理：列出全部 tag + 数量；全局改名 / 合并 / 删除。
- F11 按名称搜索。
- F12 多 tag 组合筛选（AND / OR 可切换）。
- F13 批量打 tag（多选后统一加 tag）。

**可以有（Could）**

- F14 排序（最近添加 / 名称）。
- F15 导入 / 导出 tag 数据（备份）。
- F16 自动监视文件夹变化（新增即出现，不必手动刷新）。

**本期不做（Won't）**

- 自动识别 / 生成 tag（用户明确不要）。
- 内置漫画阅读器。
- 云同步 / 多用户 / 移动端。

### 3.2 用户故事（示例）

- 作为用户，我想打开工具就看到全部漫画，这样我能总览收藏。
- 作为用户，我想点「悬疑」标签，只看悬疑类漫画。
- 作为用户，我把新漫画文件夹放进总目录后，想给它手动输入 tag（如「热血」「战斗」），也能从已有 tag 里选。
- 作为用户，我想改某本漫画的 tag：加一个、删一个、或把某个 tag 改个名。
- 作为用户，我把「恋爱」误写成「练爱」时，想全局一键改名。

## 4. 数据设计

### 4.1 概念模型

- 漫画（Comic）= 库内**含图片的最底层文件夹**：根目录下直接有图片的文件夹即一本；若某文件夹无图但有子文件夹（连载系列容器），则递归到子文件夹，每个含图片的子文件夹（如「第01卷」）即一本。唯一标识 = **相对库根的路径**（如 `连载甲/第01卷`，用 `/` 分隔）。
- 标签（Tag）= 字符串（剧情类型，如 热血 / 恋爱 / 悬疑 / 搞笑 / 日常）。
- 全局标签表 = 所有漫画 tag 的并集（自动汇总，用户不单独维护，但可全局改名 / 合并 / 删除）。

### 4.2 字段

```
Comic {
  id: string             // 唯一键，相对库根的路径（如 连载甲/第01卷）；根级单本 = 文件夹名
  series: string         // 所属系列 = 顶层文件夹名；根级单本为空
  displayName?: string    // 可选显示名，默认 = 文件夹名
  tags: string[]          // 手动维护的 tag 集合
  addedAt: datetime       // 首次入库时间（自动）
  updatedAt: datetime     // 最近修改时间（自动）
  cover?: string          // 封面文件名（自动识别或手动指定）
}
```

### 4.3 存储方案（二选一，需确认）

**方案 X — 中心索引文件（推荐默认）**

- 所有 tag 存在一个 JSON 文件里（放在工具目录，如 `data/comics.json`，与漫画库分开）。
- 优点：单文件即全部数据，备份 = 复制一个文件；读写快；实现简单；不往漫画文件夹里塞文件。
- 缺点：文件夹在资源管理器里改名后，工具里需要「重命名漫画」功能同步（或重新识别为未分类）。

**方案 Y — 每本一个 sidecar 文件（`tags.json` 放在漫画文件夹内）**

- 优点：文件夹改名 / 移动后 tag 自动跟随；和漫画一起备份天然同步。
- 缺点：每个漫画文件夹里多一个小文件；总览需扫描全部文件夹。

默认建议：**方案 X**。后续想移动漫画目录也不受影响（工具内改一下库路径即可）。

### 4.4 JSON 示例（方案 X）

```json
{
  "version": 1,
  "libraryRoot": "D:\\Comics",
  "comics": {
    "进击的巨人": {
      "displayName": "进击的巨人",

      "addedAt": "2026-08-30T10:00:00+08:00",
      "updatedAt": "2026-08-30T10:05:00+08:00",

    "间谍过家家": {

      "addedAt": "2026-08-29T21:00:00+08:00",
      "updatedAt": "2026-08-29T21:00:00+08:00"
    }
  }
}
```

## 5. 技术方案

### 方案 A：本地 Web 应用（Node 后端 + 浏览器界面）★ 推荐

- 技术：Node.js 内置模块（http / fs，**零 npm 依赖**）+ 原生 HTML / CSS / JS 前端。
- 运行：`start.bat` 双击 → 启动本机服务（仅监听 127.0.0.1）并自动打开浏览器。
- 界面：卡片网格、tag 芯片、搜索框、详情面板，现代美观，迭代快。
- 封面：后端以 http 流式返回图片，浏览器缩放 + 缓存。
- 打开文件夹：后端调用 `explorer.exe` 打开对应目录。
- 优点：UI 质量高、开发 / 改需求快、零第三方依赖、完全离线。
- 缺点：需要本机装 Node.js（当前机器已有 v24）；不是单个 exe。

### 方案 B：C# WinForms 单 exe

- 技术：与你的 DisplayRotate 相同——系统自带 csc.exe 编译 .NET Framework 4.8，单文件。
- 界面：WinForms（卡片用 FlowLayoutPanel / DataGridView + 自定义 tag 控件）。
- 优点：单个 exe 双击即用、Windows 自带运行库、延续你现有 C# 习惯。
- 缺点：界面开发量较大、观感相对朴素；改 UI 迭代慢。

### 方案 C：Electron（本期不推荐）

- 桌面窗口 + Web 技术，但体积大、依赖下载重，对单机小工具过重。

### 5.1 推荐结论

- 首选**方案 A**：快速做出好看好用的界面，方便以后加功能。
- 若你更希望「一个 exe、零 Node 依赖、延续 C# 风格」，选**方案 B** 也完全可行，工作量更大但可接受。
- 建议先按方案 A 做 MVP 验证体验，再决定是否要打包成桌面程序。

### 5.2 项目结构（方案 A）

```
comictool/
├─ server.js          # Node 服务：静态文件 + JSON API + 封面 + 打开文件夹
├─ start.bat          # 双击启动：node server.js 并打开浏览器
├─ package.json       # 仅声明，无第三方依赖
├─ public/
│  ├─ index.html      # 单页界面
│  ├─ app.js          # 前端逻辑
│  └─ style.css       # 样式
├─ data/
│  └─ comics.json     # 中心索引（方案 X）或留空用于 sidecar
└─ docs/
   └─ 需求分析与方案规划.md
```

### 5.3 API 草案（方案 A）

```
GET    /api/state                       → 漫画列表 + 全部 tag + 库路径
POST   /api/rescan                      → 扫描库目录，返回新增/消失的文件夹
GET    /api/cover?folder=<name>         → 返回该本封面图（第一张图片或 cover.jpg）
PUT    /api/comics/<folder>/tags        → 整体替换 tag 集合
POST   /api/comics/<folder>/tags        → 增加一个或多个 tag
DELETE /api/comics/<folder>/tags/<tag>  → 删除某个 tag
POST   /api/tags/rename                 → 全局改名（含合并）
POST   /api/comics/rename               → 重命名文件夹并同步索引
POST   /api/open-folder                 → 用资源管理器打开该本目录
```

安全：只绑定 127.0.0.1，仅本机可访问。

## 6. 里程碑

- M1（MVP）：扫描 + 总览 + 单选筛选 + 详情 + 打 tag / 编辑 + 数据持久化。
- M2：封面、名称搜索、未分类引导、批量打 tag。
- M3：全局标签管理（改名 / 合并 / 删除）、统计、导出备份、（可选）文件夹自动监视。

## 7. 非功能需求

- 单机离线运行，数据只存本地。
- 性能：几百本漫画扫描 < 1s；封面靠浏览器缓存。
- 备份：复制 `data/comics.json` 即完成 tag 备份。
- 平台：Windows（当前机器）。

### 2026-08-30 · M1.1 连载目录支持（递归扫描 + id 相对路径标识）

变更内容：

- **递归扫描**：根目录下文件夹不再一律当作单本。规则：含图片的文件夹 = 一本（停止下探）；无图但有子文件夹 = 连载容器，递归扫描子文件夹；两者皆无（空文件夹）= 忽略。
- **页面展示**：按「一本」（含图片的叶子文件夹）展示；连载的某一卷以「系列 / 卷名」卡片展示，系列容器本身不作为一本显示；卡片上标注所属系列（根级单本无系列标注）。
- **唯一标识升级**：由文件夹名改为相对库根的路径 id（`/` 分隔，如 `连载甲/第01卷`）。根级单本 id 仍等于文件夹名，旧数据自动兼容。
- **API 重构**：tag / 封面 / 重命名 / 打开文件夹全部改为通过 body 或 query 传 `id`（详见 README 的 API 表），避免路径含 `/` 破坏 URL 路由。
- **安全**：所有 id 统一校验（拒绝 `..`、绝对路径、非法字符），解析后必须位于库根内。
- 封面规则不变：优先 `cover.*`，否则第一张（文件名自然排序）。

已通过验证：单本 / 连载多卷 / 连载多册 / 空文件夹忽略 / 封面（cover 优先 + 自然排序）/ tag 增删改 / 全局改名 / 重命名子文件夹 / 路径穿越拒绝 / 浏览器端（设置弹窗、系列名卡片、详情、增删 tag、AND/OR 筛选、标签管理）。
